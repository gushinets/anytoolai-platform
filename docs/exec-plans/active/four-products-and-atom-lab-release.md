## Цель

Одним релизом обновить ProposalAI, Client Update Writer, Brief Decoder и Acceptance Builder и
открыть Atom Lab на VPS `yasmine` (`135.106.164.145`). Оба стека собираются из одного коммита.
Четыре продукта доступны публично без регистрации и квот. В Atom Lab участники входят по общему
коду через HTTPS из любой сети, без VPN и списка разрешённых IP. У участников общие история,
сохранённые промпты и пресеты. На всю Lab выделяются 400 запусков в сутки по UTC и до 8 задач
одновременно в очереди или работе. Допускается одно окно простоя продуктов.

| Стек | Конфигурация |
| --- | --- |
| `anytoolai-prod` | Текущий том PostgreSQL 18 `anytoolai-prod_postgres18-data`. Публичные маршруты под `/tools`. Все четыре ID в enabled и unmetered: `proposal_ai`, `client_update_writer`, `brief_decoder`, `acceptance_builder`. |
| `anytoolai-atom-lab` | Отдельные API, worker, новая PostgreSQL 18 и том `anytoolai-atom-lab_atom-lab-postgres18-data`. Порты `127.0.0.1:18114` для API и `127.0.0.1:15432` для БД. Адрес `https://any-tool-ai.ru/tools/atom-lab` через существующий Caddy, вход по общему коду. |

## 2. Одно окно. Дамп и миграция на копии

- [ ] Зафиксировать одного оператора на окно и закрыть публичный вход в продукты. Из старого
  checkout выполнить `python3 scripts/agent/runner.py prod-quiesce`. Убедиться, что во всей
  `platform.jobs` нет `created` и `running`. При таймауте оставить worker завершать задачи,
  затем повторить проверку.
- [ ] Снять один согласованный `pg_dump -Fc` по инструкции ANY-507. Зафиксировать SHA-256,
  время UTC, `alembic_version=0015`, количество строк и контрольные суммы упорядоченных строк
  по прежним колонкам.
  Хранить дамп на VPS с правами `0600`. Этот же дамп служит для репетиции и отката. Вход
  остаётся закрытым до окончания проверок нового стека.
- [ ] В checkout кандидата поднять PostgreSQL 18 в **отдельном Compose-проекте** с новым томом и
  без опубликованного порта. Использовать отдельный env-файл с нужными ролями для восстановления
  и отдельными секретами. После проверки имени проекта и тома выполнить команды ниже, где
  `rehearsal_env_file` и `prod_dump` указывают на подготовленные файлы.

  ```bash
  rehearsal=(docker compose -p anytoolai-release-rehearsal --env-file "$rehearsal_env_file"
    -f infra/compose/docker-compose.yml -f infra/compose/docker-compose.prod.yml)
  "${rehearsal[@]}" up -d --wait postgres
  "${rehearsal[@]}" exec -T postgres \
    sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --exit-on-error' < "$prod_dump"
  ```

- [ ] Сверить копию на `0015` с исходными данными. В том же проекте выполнить
  `"${rehearsal[@]}" run --rm --no-deps --build migrate`. Сервис использует продовый Dockerfile
  и entrypoint. На копии работают только PostgreSQL и одноразовый мигратор. Записать длительность
  восстановления и миграции.
- [ ] Проверить, что копия дошла до Alembic head релиза и сохранила количество строк и контрольные
  суммы по старым колонкам. Сверить цепочки сессия → job → action run → результат и `used_count`.
  У прежних jobs ожидается `consumption_mode=legacy`, у гостевых счётчиков
  `legacy_used_count=used_count` и `reserved_count=0`. Новые `execution_reservations` и
  `paid_allowance_usage` пусты. Проверить наличие таблицы `atom_lab_prompts` и колонок
  `prompt_source_ref` из `0018`.
  При ошибке копии перейти к откату с исходной схемой `0015`.
